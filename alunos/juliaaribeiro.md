## Diagnostico DORA do meu ultimo projeto

Pense no **ultimo projeto de software que voce entregou** — trabalho de
disciplina, projeto pessoal, estagio, TCC, o que for. Responda com honestidade.
Nao existe resposta errada aqui, e a nota **nao** depende de os numeros serem
bons.

- **Frequencia de implantacao:** quantas vezes aquele software foi para
  "producao" (entregue funcionando para alguem usar)?
  O sistema foi para produção uma vez. Porém, depois de disponibilizado, ficou caindo bastante porque utilizamos um sistema gratuito para hospedá-lo.

- **Lead time para mudancas:** quanto tempo passava, tipicamente, entre voce
  escrever um trecho de codigo e ele estar disponivel para o usuario?
  O sistema só ficou disponível para os usuários depois que todo o código foi implementado. Durante o desenvolvimento, não fazíamos disponibilizações frequentes.

- **Tempo de restauracao:** quando algo quebrava na apresentacao ou em uso,
  quanto tempo levava para voltar a funcionar?
  Não tivemos um problema que exigisse uma restauração, pois só disponibilizamos o sistema depois de verificar que ele estava funcionando como esperado.

- **Taxa de falha em mudancas:** que proporcao das entregas quebrou algo que
  antes funcionava?
  Como o software foi entregue somente no final do projeto e não teve manutenção depois disso, não tivemos novas entregas ou mudanças para avaliar essa taxa.

### Qual metrica era a pior, e por que

A pior métrica era a **frequência de implantação**, porque o sistema foi disponibilizado apenas uma vez durante o projeto. Além disso, depois de publicado, ele apresentou bastante instabilidade por estar hospedado em um sistema gratuito. Isso dificultou fazer novas disponibilizações e manter o sistema funcionando de forma estável.
