## Parte B — Diagnóstico DORA do meu último projeto

**Projeto:** Notebook para simulação e análise de problemas encontrados em chamadas VoIP.

| Métrica                       | Diagnóstico                                                                                                                                                 |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Frequência de implantação** | 1 entrega. O projeto só foi disponibilizado depois de finalizado, para ser entregue ao professor.                                                           |
| **Lead time para mudanças**   | Como o projeto não teve entregas intermediárias para usuários, o código só ficava disponível quando o projeto era finalizado.                               |
| **Tempo de restauração**      | O maior problema encontrado levou aproximadamente uma semana para ser resolvido.                                                                            |
| **Taxa de falha em mudanças** | Houve apenas uma entrega. Como não era utilizado controle de versões, o problema encontrado fez com que fosse necessário praticamente reescrever o projeto. |

A pior métrica do projeto era a **taxa de falha em mudanças**, principalmente pela ausência de controle de versões. Como havia apenas uma entrega e o projeto não utilizava Git ou outro sistema de versionamento, quando ocorreu um problema não havia uma versão anterior estável para recuperar. Isso fez com que a correção fosse muito mais trabalhosa e resultasse na necessidade de praticamente reescrever o projeto.
